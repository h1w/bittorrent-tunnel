# P2P and Managed Egress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add server-authorized direct tunnels and independently selectable, centrally managed egress routes for all SOCKS5 ports.

**Architecture:** Own contracts separately: NAT candidates and authenticated direct AWG carrier; persisted routes and admin UI; egress SOCKS-to-overlay protocol; local per-port selection; central authorization, real overlay/TUN integration and acceptance. Run disjoint file sets in parallel, integrate in the parent.

**Tech Stack:** Go, Linux, vendored µTP, existing AWG, bbolt, server-rendered forms, go-tui.

**Spec:** `docs/superpowers/specs/2026-11-21-p2p-egress-design.md`

## Global Constraints

One VPN IPv4 and existing TUN per device. Hub ACL authority; do not publish client endpoints to DHT. Direct AWG ext-utp first; existing authorized hub path is fallback. Named route failure never chooses a different exit or drops a required transit. Hub default permitted only by Internet ACL. Roles and router mappings opt-in. Bind role service to authenticated overlay, never WAN. Authentication and CSRF for mutations. No host default-route change. No test mocks in shipping code. All independently selected scopes have separate file owners; parent runs integration, checks, and dispatches review.

## Review Focus

Source spoofing and old/stale grants; live revocation of active P2P and exit streams; mismatched member/hop or copied token; unauthorized use of a destination/LAN; concurrent role/catalog changes and shutdown; fixed and all three balancing ports never change selected egress; simultaneous hole-punch attempts, duplicate sessions and NAT lease lifecycle.
