# Прямой P2P, выходные узлы и каскады btawg

Хаб остаётся источником идентичности, ACL и каталога маршрутов. VPN-IPv4 и подсеть группы неизменны. Старые импорты, нативные экспорты и 13 SOCKS5-портов сохраняются; новые функции включаются управляемым клиентом. Системный default route не меняется.

## P2P

Из существующего аутентифицированного overlay хаб проверяет обе стороны ACL и выдаёт возобновляемые короткоживущие разрешения с VPN-IP, ключом и кандидатами пары. Разрешения действуют лишь пока клиенты продлевают их. Запросы на соединение раскрывают кандидатов только допущенному пиру; оба клиента локально разрешают P2P. Дополнительное разрешение на выход/транзит относится только к службам маршрута и не расширяет обычный межклиентский ACL. Клиент проверяет криптографический ключ и IP источника входящих пакетов; при отзыве закрывает путь. У старых/недоступных клиентов пакеты по-прежнему идут через хаб там, где это разрешено.

Первый прямой bearer: AWG внутри BitTorrent `extended` по µTP. Один долгоживущий UDP-сокет на семейство адресов, точный внешний endpoint определяется проверкой с того же сокета через хаб. Пробуются локальная IPv4 LAN, публичный или вручную проброшенный IPv4, маппинги UPnP IGD, NAT-PMP и PCP, глобальный IPv6 и двусторонний UDP hole punching. Подтверждается связность между A и B, а не просто ответ шлюза. DHT остаётся альтернативным поиском хаба, не публикует адреса устройств. Если прямой bearer исчезает, обычный VPN-трафик возвращается на существующий путь через хаб. Не обещаем успех через произвольный NAT или классификацию нового сигналинга обычным BitTorrent.

## Выходы и каскады

Админ регистрирует выходные/транзитные устройства и создаёт именованный маршрут с одним выходом либо с упорядоченной парой транзит → выход. Разрешения — ID клиентов и/или групп. Маршруты не разрешают LAN, overlay или адреса самого хоста. Локальные роли клиента и автоматическое открытие портов требуют явного opt-in. Устройство исходящего маршрута привязывает удалённую сторону к аутентифицированному overlay, валидирует право инициатора на конкретный маршрут, позицию и предыдущий хоп; один пользователь не может сесть на чужой маршрут или пропустить обязательный хоп. Нет открытого WAN-прокси. TCP и UDP поддерживаются, финальная нода резолвит имена. Узел транзита в этой схеме доверенный и может видеть метаданные. Не обещаем анонимность. Утрата разрешения прекращает также активные соединения по истечении короткой аренды, а при доступном управляющем канале при следующем обновлении.

## Веб-панель и TUI

Отдельный раздел Routes с ролями узлов и CRUD маршрутов; выбор узлов, разрешённых клиентов/групп, явный порядок. Отозванные и удалённые устройства не могут обслуживать маршруты. У всех портов 1080–1092 отдельный список разрешённых выходов, включая хаб при разрешённом Internet. Выбранный ID сохраняется; переименование не переключает маршрут. Порты не переключаются на хаб/системный Интернет/другой выход при отказе. Допустим резервный физический путь до **того же** узла. Смена выбранного выхода действует для новых CONNECT/UDP ASSOCIATE; политика отзыва закрывает активные соединения. Балансировщик выбирает только транспорт и держит TCP/UDP-сессию на выбранном маршруте. Настройка транспорта/приоритетов остаётся доступна.

## Рассмотренные варианты

Публичная mesh-discovery через DHT не даёт приватности ACL и не решает смену адреса от NAT. Оставить всё через хаб проще, но исключает прямой путь. Выбран хаб-координатор плюс прямой канал и действующий резерв. Выходы сделаны на уровне SOCKS5, не через перехват системного default route: это позволяет выбрать независимый маршрут для каждого порта и сохранить совместимость. Не используем скрытый fallback между странами.

## Приёмка

Стенд покрывает входящие и исходящие VPN-пакеты, ACL deny/revoke, потерю хаба, переустановку по другому адресу, прямой/резервный путь, LAN/IPv6/наблюдаемый UDP и каждый mapping протокол, два последовательных хопа, IPv4/TCP/UDP за выходом, DNS только на финальном узле, недоступный хоп без смены выхода, POST auth/CSRF, сохранение выбора 13 портов и реальные действия в веб-панели/TUI. Полный `go test ./...`, race detector для всех затронутых сетевых и управляющих пакетов, независимое ревью кода и гонок. Недостижимый физический NAT/оборудование указывается как ограничение проверки.
