# Управление btawg через systemd, несколько SOCKS5 и панель в VPN

## Цель и базовая версия

Linux, существующие два бинарника, общая IPv4-сеть группы и один центральный сервер. Изолированная рабочая копия от `origin/main` (v0.3.1). Все десять режимов из `config.ClientModes()`; исследовательские эксперименты не добавляют режимов в релиз. Публичные порты управляемого сервера фиксированы: BitTorrent 6881/TCP и UDP, WG 51820/UDP, AWG 51821/UDP. DHT остаётся альтернативой для BitTorrent; самопроизвольного перехода на другой транспорт нет.

## Рассмотренные варианты

- Второй адрес на каждый транспорт упростил бы demux ответов, но занял бы до десяти адресов группы на пользователя и изменил видимые адреса. Выбрано сохранить один VPN-IP и закрепить обратный маршрут каждого соединения за принявшим его транспортом.
- Единственный выбранный туннель с несколькими слушателями не подходит: галочки должны независимо управлять реальными соединениями. Общий сервис с несколькими независимыми туннелями позволяет не перезапускать остальные при переключении.
- Перезапуск systemd-сервиса при редактировании настроек оборвал бы все соединения. Управляющий Unix-сокет принимает изменения у запущенного демона; когда сервис остановлен, TUI сохраняет настройки для следующего запуска.

## Установка и TUI

- `sudo ./btawg-server install` и `sudo ./btawg-client install -import-file FILE` устанавливают соответствующий исполняемый файл и unit, запускают и включают автозапуск. Клиентский импорт можно ввести без копирования секрета в аргументы процесса. Установка повторяема, не переинициализирует существующее состояние. При обновлении бинарника применить его через systemd, сохранив конфигурацию. Явная миграция существующей серверной базы не пересоздаёт пользователей, ключи или пароль.
- После первой серверной установки вывести `admin` и сгенерированный пароль в текущий терминал, не в journal. В базе — bcrypt-хеш. Ошибки установки видимы и не теряют уже созданные начальные учётные данные.
- Бинарники без аргументов открывают TUI; systemd вызывает явную команду запуска демона. В TUI: текущий статус, запуск, остановка, перезапуск и автозапуск. Управление и чтение секретов доступны только администратору машины. Для существующих ручных запусков оставить поддерживаемый явный foreground-вход, обновить команды, которые выдаёт панель.
- Серверный конфиг запуска хранится под `/etc/btawg`, данные панели, группы, пользователи и ключи — в bbolt под `/var/lib/btawg`. Клиентский конфиг хранится под `/etc/btawg`; включает импорт, выбранные режимы и пару SOCKS5-учётных данных. Секретные файлы `0600`, атомарное сохранение. Сокет управления — root-only в `/run/btawg-client`; запускаемый процесс сообщает systemd о готовности после подготовки слушателей. Не менять правила входящих портов хоста.

## Панель и маршрутизация

- Одна HTTP-панель, вход и сессии общие: `127.0.0.1:<panel_port>` и VPN-адрес сервера (по умолчанию `10.77.0.1:8080`). Не слушать публичный адрес. В обычном Linux-режиме VPN-слушатель ограничен TUN-интерфейсом; для userspace (сценарии тестов/отладки) — VPN netstack. Подключение к панели из группы использует её штатный VPN-маршрут, в том числе когда интернет для клиента отключён. Первичная настройка снаружи — SSH port forwarding до создания клиента. Если фаервол владельца блокирует вход или форвардинг, приложение его политику не переписывает.
- Один VPN-IP пользователя во всех десяти режимах; смешанные клиенты остаются в общей подсети группы. Сервер различает активные криптографические пути (AWG-устройства по BitTorrent-режиму, отдельные прямые AWG/WG, TLS-сеансы по паре пользователь + режим). Входящий аутентифицированный поток закрепляет обратный IPv4 путь за своим транспортом; несовпадающий путь не перехватывает активный поток. Для входящего нового соединения к VPN-IP сохраняется штатный доступ через основной активный путь; смена режима не перемещает существующие SOCKS-сеансы на другой способ. Просроченные/закрытые потоки и отозванные пользователи освобождают состояние; правила групп, блокировки интернета и учёт трафика продолжают действовать.
- Один автоматически выбранный активный режим обслуживает обычный IPv4-доступ хоста к подсетям VPN через Linux TUN; метод SOCKS определяется портом, а не основным маршрутом. Параллельные прокси используют изолированные пути и уникальные локальные TCP/UDP endpoint на VPN-IP, включая DNS-запросы. btawg настраивает адреса, VPN-маршруты, частные таблицы прокси и серверный NAT/форвардинг; системный default route клиента не меняется. Импорт содержит необходимые VPN-префиксы. Удаляются только адреса и правила, принадлежащие приложению.

## Порты и учётные данные SOCKS5

| Порт | Режим |
|---|---|
| 1080 | `socks5-awg-ext-utp` |
| 1081 | `socks5-awg-ext-tcp` |
| 1082 | `socks5-awg-req-utp` |
| 1083 | `socks5-awg-req-tcp` |
| 1084 | `socks5-awg-udp` |
| 1085 | `socks5-wg-udp` |
| 1086 | `socks5-ext-utp` |
| 1087 | `socks5-ext-tcp` |
| 1088 | `socks5-req-utp` |
| 1089 | `socks5-req-tcp` |

Изначально отмечен режим импорта. Другие можно включать независимо. Все десять TCP-портов заняты клиентским демоном, пока он работает. На выключенном порту демон не проксирует, а закрывает принятые соединения; порт никогда не назначается другому режиму. Выключение закрывает TCP CONNECT и UDP ASSOCIATE данного метода, остальные продолжают работать. Остановка всего сервиса освобождает все порты. По умолчанию SOCKS5 доступен только на loopback; явная настройка LAN-адреса сохраняется.

Один сгенерированный логин и пароль для всех локальных входов, SOCKS5 username/password (RFC 1929), без обхода no-auth. TUI показывает пару по явному действию и позволяет её перегенерировать. После ротации старые данные не принимаются ни на одном порту; уже авторизованные сессии закрываются. Обычный SOCKS5 не шифрует свои учётные данные — LAN-вход лишь для доверенной сети. Секреты не печатаются в журнал и не передаются через параметры этих управляющих команд.

Макет клиентского TUI:

```text
btawg-client  active / enabled
[x] 1080  socks5-awg-ext-utp   connected
[ ] 1081  socks5-awg-ext-tcp   reserved
...
Space: переключить  v: показать логин/пароль  g: сменить
s: запуск  t: остановка  r: перезапуск  b: автозапуск  q: выход
```

## Проверка

Проверить unit и создание/повторную установку, живые действия обоих TUI, панель из отдельного клиента через VPN и недоступность по публичному интерфейсу. Независимый egress TCP и UDP на нескольких одновременных транспортах одного VPN-IP, сохранение доступности других портов при выключении, захват выключенного порта другим процессом должен быть невозможен. Проверить общие учётные данные до и после ротации, отказ no-auth, сохранение конфигурации и серверной личности после рестарта, отсутствие ручной настройки маршрутов в чистых Linux namespaces и сохранение группы/правил доступа.
